# Project Memory Bank

## Current Status

Telegram dispatch bot for short-haul inter-facility shuttle tracking. Runs on an
AWS `t3.xlarge` under Docker: `mysql:8.0` plus a `python:3.11-slim` bot container.

As of 2026-08-29 the codebase has a test suite and six previously-shipping defects
have been fixed. Work sits on branch `fix/state-machine-regressions` (11 commits,
**not yet pushed**; `main` is untouched at `cd5ad06`).

**Clarification that has caused confusion:** earlier notes said the codebase was
"transitioned to Qwen 2.5 Coder 14B". That referred to a *local coding assistant*,
never to the bot itself. Runtime text parsing and vision OCR both call the Gemini
API. There is no local LLM in the request path, and none would be practical on a
`t3.xlarge` (4 vCPU, no GPU).

## Architecture & Tech Stack

- **Language:** Python 3.11
- **Infrastructure:** one `docker-compose.yml`, two containers (`mysql_db`, `telegram_bot`)
- **Scope:** 6 Python files in `bot/`, 3 in `tests/`
- **AI:** Gemini via `google-genai`. Text intent in `parse_text_with_llm`,
  document OCR in `extract_bol_locally`.

## Critical Fixes & Constraints (DO NOT OVERWRITE)

- **`bot/schema_ddl.py` is the only schema definition.** `main.py` and the tests
  both apply it. `init.sql` and `schema.sql` were deleted for drifting out of sync.
  Never add a second copy.
- **Dependency deadlock:** `python-telegram-bot` 20.8 needs `httpx~=0.26`;
  `google-genai` 2.x needs `httpx>=0.28.1`. Incompatible. `google-genai` is pinned
  to 1.2.0. Upgrading it requires moving PTB to 22.x first.
- **Model choice is deliberate.** `MODEL_NAME = "gemini-flash-lite-latest"`.
  Measured 2026-08-28: `gemini-3.5-flash-lite` succeeded on 3/5 calls,
  `gemini-flash-lite-latest` on 5/5, `gemini-2.5-flash-lite` returned 404 on
  `v1beta` despite being listed by ListModels. Verify model IDs against the API,
  never from memory.
- **Gemini calls must stay in an executor.** `parse_text_with_llm` and
  `extract_bol_locally` are blocking and now retry for up to ~15s. Called inline
  from async code they freeze the bot for every driver.
- **A parse failure must never return `NONE_WORK_RELATED`.** That is
  indistinguishable from casual chat and the message is silently discarded. Use
  `PARSE_FAILED`, which raises a dispatch card carrying the driver's own words.
- **A duplicate BOL is a driver error, not something to override.** It means the
  previous load's paperwork was attached. Record the movement, discard every
  document-derived field, and card dispatch to request a repost. The old
  "Force Save Duplicate" button was removed; it wrote into a UNIQUE index and
  could never have worked.
- **MySQL cannot live on a `/mnt/c` bind mount** — InnoDB will not initialise on
  drvfs. Local runs use a named volume; production keeps `MYSQL_DATA_PATH`.
- **Never run `telegram_bot` locally against the production token.** One
  `getUpdates` poller per token; a second conflicts with EC2 and can swallow
  live driver messages.

## Defects fixed on this branch

1. Arrival wiped a previously captured receiver POD (`COALESCE` fed `0`, not `NULL`).
2. Mid-shift POD enforcement was dead code — it never fired for any driver.
3. The duplicate-BOL guard ran before the match block, making three patch paths unreachable.
4. Bobtail detection matched `"bt"` as a substring, so "doubt" and "debt" flagged bobtail.
5. Gemini outages silently dropped truck movements.
6. "Force Save Duplicate" wrote a duplicate into a UNIQUE index.
